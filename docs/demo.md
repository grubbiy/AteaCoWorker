# A three-minute CoWorker demonstration

## Opening — 20 seconds

“CoWorker is a proposed local workspace for project knowledge. Prepare online, then keep creating offline. This website is an interactive concept, not the actual AI application.”

Let the hero animation show Prepare → Disconnect → Create, or use the pause control and select each step. The six-step guided tour explains the same story.

## Prepare — 35 seconds

Go to **Sources**. Inspect the brief. Explain the bounded approved folder and optional local notes. Leave the sample selection as-is, click **Review & prepare**, and approve the pack. Watch the four simulated stages. Call out **Ready with gaps**: the pricing appendix is missing, and the demo admits it.

## Disconnect and ask — 35 seconds

Switch **Online mode** to **Offline Lock**. Visit **Assistant**, choose **Prepare the workshop**, and click a citation. It opens the captured source passage without opening SharePoint. Ask **What’s the budget?** to demonstrate the evidence gap.

“The intended app would run its model locally. Here, these answers are scripted to let us test the workflow.”

## Make something — 45 seconds

Save a useful answer to Notes. Open **Document**, create the sample plan, edit a sentence, and review the shorter opening. Apply and undo it. Open **Slides**, approve the outline, then edit a slide title. Markdown downloads work; Word and PowerPoint export are future application features.

## Adapt and extend — 30 seconds

In **Settings**, compare Light, Balanced, and Performance. Open Advanced settings and change the context budget. These demonstrate proposed controls, not hardware compatibility measurements.

In **Coding lab**, inspect the proposed diff. Offline Lock prevents internet approval. Applying the sample changes only the demo state; no code executes. Real OS-enforced isolation is a requirement to validate later.

## Reconnect — 15 seconds

Switch Offline Lock off. Click **Refresh pack**. Review the workshop date change and approve it. The captured source moves to v1.1, and your document remains unchanged with a review notice.

## Close — 20 seconds

Scroll to the value calculator. Change inputs using actual assumptions from a future pilot, not invented claims. “For suitable workloads, fewer paid seats might be needed. The pilot must prove quality, useful performance, safe operation, and net cost.”

## Suggested tester questions

1. Can you explain Prepare for offline in one sentence?
2. Is it clear which sources enter the project and why?
3. Could you tell the difference between online mode and permission to use the internet?
4. Did the missing budget and clickable evidence make the answer easier to assess?
5. What would you want to create offline first?
6. What hardware do you use, and which performance tradeoff would you accept?
7. What would you need to see before trusting a coding workspace?

Do not collect real work documents or confidential information through this demo. Use **Reset demo** after testing or clear this site's browser data.
